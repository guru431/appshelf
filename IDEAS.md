## 2026-10-21 · Проверка целостности полки без автоматического удаления [P3]
**Context:** аудит `store.versions`, публикации, сетевого архива и раздела README «Резервная копия»; автоматическая уборка сирот ранее отклонена в IDEAS-archive.md.
**What:** диагностический отчёт показывает, существуют ли IPA, иконки и manifest каждой версии, совпадают ли размер, itemId, bundle id и ссылки с базой, есть ли незавершённые переносы. Отдельно отображаются файлы без строк и строки без файлов, без попытки автоматически удалять неизвестные каталоги.
**Proposal:** read-only CLI с кратким итогом и машинным JSON; по желанию — сохранённый SHA-256 после скачивания и периодическая углублённая проверка. Обязательные поля IPA (включая external version id) проверять до принятия версии: локальная проба показала, что `read_info` сейчас принимает отсутствующий external id как пустую строку. Критерий: повреждённый/пропавший файл и неверный URL обнаруживаются без изменения базы и архива; токены и данные покупателя не попадают в общий отчёт.
**Status:** proposed

## 2026-10-21 · Согласованный бэкап с проверяемым восстановлением [P3]
**Context:** README ru/en описывают снимок SQLite и отдельную копию архива; ротация версий и смена токена меняют архив независимо от копирования базы.
**What:** владелец получает набор восстановления с согласованным снимком базы, перечнем версий и контрольными суммами, а также проверкой доступности всех IPA, на которые ссылается снимок. Простое наличие двух резервных копий ещё не показывает, можно ли из них восстановить полку целиком.
**Proposal:** отдельная команда подготовки набора: короткая согласованная фиксация состояния/защита копируемых версий, затем копирование и проверка, секреты — отдельно в защищённом хранилище. Добавить проверку восстановления в изолированном каталоге без Apple и без отправки писем. Учесть согласованность с rotate-token и обеими службами; скачивание всего архива в память или на малый локальный диск не требуется.
**Status:** proposed

## 2026-10-21 · Понятная очередь и результат длительных проверок [P3]
**Context:** `jobs.Worker`, `removed.check`, `/api/status`, шаблоны «История» и «Удалённые»; сейчас видны в основном busy и состояние приложений.
**What:** участник видит, сколько ID уже проверено, сколько осталось, что ждёт входа, сколько найдено своих и сколько проверок завершились технической ошибкой. Ошибка отдельного ID отличается от подтверждённого «нет лицензии»; после окончания доступен результат, даже если страница была закрыта.
**Proposal:** сохранять ограниченный набор счётчиков и итог задания; отдавать только сведения активной полки через существующий опрос. Не изображать процент скачивания, если ipatool не даёт надёжных данных. Критерий: прогресс переживает перезагрузку страницы, частичный сбой виден, данные других Apple ID недоступны; это пользовательский экран, отдельный heartbeat службы не предлагается.
**Status:** proposed

## 2026-10-21 · Проверить обновление одного приложения по кнопке [P3]
**Context:** каталог, `nightly._run_account`, `store.retry`; при рабочей current и ошибке обновления карточка оставляет установку, а повтор обновления ждёт ночи.
**What:** участник может запросить последнюю версию конкретного приложения сразу, сохраняя доступную current при отказе Apple. Не требуется запускать проверку всей истории и всего справочника ради одного приложения.
**Proposal:** действие «Проверить обновление» ставит отдельное дедуплицированное задание с проверкой сессии и места; повторные нажатия не плодят обращения. Показывать время последней проверки и результат «новее нет / скачана версия / ошибка»; метка относится к полке, а не к установленной версии на телефоне. Определение версии на устройстве, отклонённое 2026-10-13, не возвращать.
**Status:** proposed

## 2026-10-21 · Закрепление нужной архивной версии перед следующей ротацией [P3]
**Context:** `store.add_version` всегда сохраняет только current и previous; в первоначальной спецификации полный архив всех версий был вне рамок.
**What:** участник по явному выбору сохраняет одну важную версию, например последний работающий банковский клиент, даже когда выходят следующие две. Это отдельная возможность сверх нынешних двух слотов, а не требование хранить все версии каждого приложения.
**Proposal:** ограниченный слот «сохранённая версия» с видимым размером, снятием закрепления и обычной установочной ссылкой. Критерий: третье обновление не удаляет закреплённый IPA, общий резерв места соблюдён. Сохранение IPA не гарантирует совместимость старой версии с данными после обновления приложения; описывать границы отката отдельно от возможности скачать файл.
**Status:** proposed

## 2026-10-21 · Группы по бренду и избранное для банковских приложений-клонов [P3]
**Context:** `appshelf/data/removed_apps.json`, `/blocked`, `/history`; справочник содержит много разных названий и ID одного банка.
**What:** участник находит приложения своего банка по устойчивому бренду и отмечает нужные в избранное, даже если очередной клон имеет несвязанное название. Сейчас aliases помогают поиску, но не показывают структуру множества клонов.
**Proposal:** необязательные brand/category в справочнике и личное избранное в пределах полки; рядом сохранять точное имя, ID, версию и результат проверки лицензии. Не объявлять клон официальным или безопасным только по бренду. Критерий: поиск по банку показывает связанные ID, а несколько клонов не объединяются в одну покупку или установочную запись.
**Status:** proposed

## 2026-10-21 · Управление отдельными входами на устройствах [P3]
**Context:** `webauth` использует годовые записи, а `users.epoch` отзывает сразу все входы одного участника.
**What:** участник видит свои активные входы с понятной меткой устройства и может отозвать потерянный телефон, сохранив вход на остальных. Общая полка и личные участники по-прежнему разделены.
**Proposal:** серверный идентификатор сессии, дата создания/последней активности и индивидуальный отзыв; не считать User-Agent доказательством личности устройства. Согласовать срок хранения и минимальный набор сведений, оставить «Выйти везде». Критерий: отзыв одного входа участника не гасит соседнего участника в том же браузере и не требует замены входа Apple ID на другой способ авторизации.
**Status:** proposed
