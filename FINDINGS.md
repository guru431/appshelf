## 2026-10-12 · Вход нового Apple ID «истёк» через полторы минуты после входа [P2]
**Context:** первый вход приглашённого участника 10:43:59 UTC: `refresh_history` прошёл (10:44:07), `check_removed` проверил 73 приложения и на 74-м (Авито, 417281773) получил от `list-versions` выход 3 → `mark_expired`, задание ждёт входа. Сразу после этого `list-purchases` того же Apple ID — тоже выход 3 (DAAP 401/403), у двух других новых Apple ID того же дня вход жив.
**What:** почему токен умер, не установлено. На Авито мёртвый вход этого Apple ID получает 401 `2042 MZCommerce.AuthTokenResumeFreeBuy`, а на другие бесплатные приложения — обычное 9610; живой вход другого участника на Авито — 9610 и остаётся жив. Два прочтения: токен отозвал Apple сам (до этого — серия неверных паролей к этому Apple ID), или его убил именно запрос по Авито.
**Proposal:** сделано: `check_removed` на «вход истёк» по одному приложению проверяет вход списком покупок — жив: приложение считается «нет лицензии», проверка идёт дальше; истёк: id запоминается (после нового входа проверка начнёт не с него), строка в журнале `appshelf-web` в обоих случаях. Осталось: участник входит заново → `journalctl -u appshelf-web | grep "Apple ID #4"` и `list-purchases` через пару минут. Вход жив — закрыть; снова истёк — смотреть строку журнала.
