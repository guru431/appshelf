## 2026-10-12 · «Добавить Apple ID» при активной общей полке отдаёт новый Apple ID общему участнику [P1]
**Context:** ревью ветки `multi-signin` (spec 2026-10-12 §4, §6.3); `appshelf/web/accounts.py` (`/apple/add`), `appshelf/web/signin.py` (`decide`, `register`), подсказка в `appshelf/web/templates/login.html`.
**What:** новый для сервера Apple ID из «Добавить» достаётся человеку активной полки. Если активна полка общего Apple ID (или в браузере вошёл только он), личный Apple ID становится полкой общего участника: её видит, публикует и удаляет каждый, кто входит общим Apple ID, а добавивший сохраняет доступ к общей полке и после смены её пароля с «Выйти на всех устройствах». Вернуть Apple ID себе в панели нельзя — только удалить полку. Форма называет получателя лишь при двух и более вошедших, имя участника может совпадать с именем другого, а `GET /acct/<id>` меняет активную полку и по ссылке с чужого сайта.
**Proposal:** нужно решение владельца. Минимум — подсказка всегда называет получателя и его активную полку и говорит о последствии («её увидит каждый, кто входит Apple ID этого участника; отдельным участником Apple ID становится по приглашению»), та же фраза в README. Строже — спрашивать на форме, к кому добавить, или не добавлять новые Apple ID участнику, отмеченному как общий.
**Status:** open

## 2026-10-12 · Незавершённый шаг «Добавить Apple ID» переживает «Выйти на всех устройствах» [P1]
**Context:** ревью ветки `multi-signin`; `appshelf/web/signin.py` (`register`, `complete`, `/login/code`). На `main` так же — ветка этого не вносила.
**What:** «Добавить» с новым Apple ID дошло до шага кода, человеку сделали «Выйти на всех устройствах», затем введён верный код: Apple ID привязывается к этому человеку, а браузер получает действующую запись с новым `epoch`. Тот, у кого была чужая cookie, за 10 минут шага закрепляет доступ своим Apple ID. Тест `test_add_form_renders_when_browser_session_is_gone` держит только половину с неверным кодом.
**Proposal:** в `/login/code` рядом с проверкой «Apple ID удалили»: для нового Apple ID из «Добавить» (`pending.account_id is None and pending.user_id is not None`) требовать, чтобы `pending.user_id` был среди вошедших (`w.signed`), иначе отменить вход, удалить временный HOME и отказать. Тест на верный код после «Выйти везде».
**Status:** open

## 2026-10-12 · «Выйти везде» самому себе в «Участниках» при вошедшем соседе — голый 403 [P3]
**Context:** ревью ветки `multi-signin`; `appshelf/web/admin.py` (`/admin/users/<id>/logout-all`).
**What:** владелец гасит себя на странице «Участники», а в браузере вошёл ещё кто-то: переход назад на `/admin` отвечает `{"detail":"только владельцу"}` вместо страницы. До ветки владелец попадал на `/login`.
**Proposal:** если погашен вошедший в этом браузере владелец — переходить на `/`.
**Status:** open

## 2026-10-12 · Два одновременных удаления полок владельца оставляют сервер без владельца [P3]
**Context:** ревью ветки `multi-signin`; `appshelf/web/accounts.py` (`refusal`), `appshelf/jobs.py` (`remove_account`). Было и до ветки.
**What:** «последний Apple ID владельца» проверяется по списку полок на начало запроса: два удаления двух полок владельца в один момент оба проходят проверку.
**Proposal:** перепроверять в транзакции `remove_account`: человек — владелец и Apple ID у него последний → отказ.
**Status:** open

## 2026-10-12 · Мелочи ревью `multi-signin`: тест, имя, докстринг, строка спецификации [P3]
**Context:** ревью ветки `multi-signin`; `tests/test_signin.py`, `appshelf/web/signin.py`, spec 2026-10-12 §6.2.
**What:** (1) для `/logout-all/<id>` последнего человека проверен только ответ 303, а не «как „Выйти“» — переход на `/login` и удалённая cookie; (2) `here()` в `signin.py` спорит по смыслу с переменной шаблонов `here` (адрес страницы); (3) докстринг `submit` говорит «user_id вошедшего человека» — теперь это человек активной полки; (4) spec §6.2 не оговаривает, что «Убрать с этого устройства» скрыта, когда вошёл один человек.
**Proposal:** дописать две проверки в тест, переименовать `here` → `signed_here`, поправить докстринг и полстроки спецификации.
**Status:** open
