## 2026-10-29 · Версия из Play, пришедшая набором файлов, больше не запрашивается [P3]
**Context:** самопроверка этапа 4 (отложено, было только в журнале исполнителя), `appshelf/android/fetch.py:217–235` (`check_app`, `source_etag = split:<vc>`).
**What:** если новая версия из Play пришла только набором файлов, карточка запоминает `split:<vc>`, и в следующие ночи эту версию уже не запрашивают, даже если Play потом начнёт отдавать её одним APK. Обновление придёт только со следующей версией.
**Proposal:** по «Проверить обновление» запрашивать delivery и для `split:<vc>`, либо повторять раз в неделю.
**Status:** open

## 2026-10-29 · Итог ночи без входа в Apple ID показывает Android-часть в Apple-каталоге [P3]
**Context:** самопроверка этапа 1 (отложено, было только в журнале исполнителя), `appshelf/nightly.py:39–47`, `result_for` (`nightly.py:124–131`).
**What:** когда входа нет ни в один Apple ID, итог ночи — `NO_LOGIN + " | Android: …"`. В нём нет «@», поэтому `result_for` отдаёт Apple-каталогу всю строку вместе с Android-частью. Это косметика.
**Proposal:** в `result_for` отрезать часть, начинающуюся с `Android: `.
**Status:** open

## 2026-10-29 · Задание add RuStore по снятой с полки карточке сначала качает APK [P3]

## 2026-10-29 · Ревью Android: метка «подписан не так, как в RuStore» пропадает после неудачной ночи [P3]
**Context:** ревью всей Android-работы (план этапа 5, Task 6), `appshelf/android/fetch.py` — `app_failed`, `check_app`; решение Task 5 «метка в last_error».
**What:** метка сверки живёт в `android_apps.last_error`; ночь с ошибкой источника пишет туда текст ошибки, следующая ночь «новее нет» — пусто: защитная подсказка («не встанет поверх версии из RuStore») пропадает до новой версии.
**Proposal:** не затирать метку в `app_failed`, пока есть текущая версия (ошибку — отдельной строкой), или хранить метку отдельным полем (схема 9).
**Status:** open

## 2026-10-29 · Ревью Android: подпись APK не проверяется криптографически, v3 берётся раньше v2 [P3]
**Context:** ревью всей Android-работы, `appshelf/apk.py:254` (`_block_cert`).
**What:** отпечаток — из сертификата блока v3, иначе v2, иначе v1, без проверки самих подписей. Файл со скопированным v3-блоком разработчика и действующей v2 злоумышленника покажет на полке отпечаток разработчика; Android 7–8 при новой установке поставит его по v2 (обновление поверх и Android 9+ — не примут).
**Proposal:** записать ограничение в README («отпечаток — из сертификата, подпись не проверяется»); или сверять, что сертификаты v2 и v3 совпадают, иначе отказ.
**Status:** open

## 2026-10-29 · Ревью Android: редиректы повторяют заголовки и тело запросов с секретами [P3]
**Context:** ревью всей Android-работы, `appshelf/android/net.py:290, 303` (`Http._request`).
**What:** на 307/308 POST уходит с тем же телом (`Token=<AAS>` в `/auth`, `client_secret` в token endpoint), а `Authorization`/`Cookie` — на хост редиректа, любой https-хост. Устроить это может только сам Google, поэтому P3.
**Proposal:** для `/auth`, `fdfe` и token endpoint Google редиректы не отслеживать (параметр `follow=False`) или снимать чувствительные заголовки и тело при смене хоста.
**Status:** open
