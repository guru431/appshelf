## 2026-11-12 · Сбой копирования на публичную полку раскрывает токен личной Android-полки владельца [P1]
**Context:** адверсариальный аудит 2026-11-12, линза «безопасность» (верификатор воспроизвёл скретч-тестом), `appshelf/android/fetch.py:410-414` (`_copy_to_public`), `appshelf/jobs.py:125` (`describe`).
**What:** `shutil.copyfile` и `read_bytes` читают APK и icon.png с личной полки владельца без перехвата: OSError (пропавший файл, сбой CIFS) с полным путём `<архив>/<токен личной полки>/…` через `jobs.describe` попадает в `android_jobs.error` и `last_error` публичной карточки — его видят участники на /android/public, а при «Сравнить и добавить версии» и гости /p. По этому токену `/apk/<токен>/<пакет>.apk` без входа отдаёт любое приложение личной полки, включая купленное в Google Play.
**Proposal:** в `_copy_to_public` перехватывать OSError чтения исходной полки: `raise SourceError("APK на полке владельца сейчас недоступен — повторите позже") from None`; в `jobs.describe` для OSError писать `e.strerror` без `e.filename` (как в `android/net.py`). Тест: удалённый исходный APK не кладёт токен ни в `last_error`, ни в `android_jobs.error`. Если такой сбой уже случался на сервере — сменить токен личной полки (`rotate-token --android`).
**Status:** open

## 2026-11-12 · Вход: повторный шаг кода отдаёт итог чужого входа без сверки кода (обход 2FA) [P2]
**Context:** адверсариальный аудит 2026-11-12, линза «безопасность» (воспроизведено на уровне `LoginFlow`), `appshelf/web/login.py:170-178` (`start`), `:223-236` (`finish`), `appshelf/web/signin.py:303-319` (`login_code`).
**What:** второй `start` с тем же Apple ID и паролем из другого браузера, пока шаг 1 ждёт Apple, получает flow_id чужого входа; после того как владелец входа ввёл верный код, `finish` ещё `join_wait` (150 с) отдаёт `LoginFinished(итог)` любому запросу с этим flow_id, не сравнивая код. `login_code` вызывает `admitted` без `how`, поэтому письма «вход на новом устройстве» нет: знающий пароль и попавший в окно шага 1 (секунды) входит участником без второго фактора.
**Proposal:** хранить в `_Finishing` хэш кода первого запроса и отдавать `LoginFinished`/`LoginJoined` только при совпадении (`hmac.compare_digest`) — двойное «Войти» из того же браузера шлёт тот же код; иначе `LoginExpired` и неудача в Limiter. По желанию — привязать присоединение в `start` к браузеру нонсом в cookie формы. Тест: второй `finish` с другим кодом → `LoginExpired`.
**Status:** open

## 2026-11-12 · F-Droid: Java проверяет index-v1.json, а каталог берётся из неподписанного entry.json того же jar [P2]
**Context:** адверсариальный аудит 2026-11-12, линза «недоверенный ввод» (PoC верификатора), `appshelf/android/fdroid_index.py:252,266` (`_index_data`, `verify`).
**What:** `verify()` выбирает файл для Java по содержимому entry.json (`"index" in _index_data(raw)`), а `_index_data`, `parse` и `index_timestamp` читают entry.json всегда, когда он есть. Jar с подлинным подписанным index-v1.json и неподписанным entry.json без ключа "index" проходит проверку, а имена файлов, SHA-256, ожидаемого подписанта APK и время каталога (защиту от отката) задаёт неподписанный файл. Условия: контроль над HTTPS-ответами репозитория (от этого и защищает закреплённый ключ) и подписанный тем же ключом index-v1.json в пределе 8 МиБ.
**Proposal:** выбирать имя файла один раз по составу архива, отдавать Java на проверку именно его и разбирать JSON только после успешной проверки. Тест: jar с подписанным index-v1.json и неподписанным entry.json без "index" отклоняется.
**Status:** open

## 2026-11-12 · Иконка APK: каждая ссылка заново разбирает resources.arsc — маленький APK держит обработчик часами [P2]
**Context:** адверсариальный аудит 2026-11-12, линза «недоверенный ввод» (замер верификатора), `appshelf/apk_icons.py:83` (`render_icon.resolve`/`drawable`), вызов из `appshelf/android/fetch.py:125` (`store_apk`).
**What:** `resolve()` на каждый переход по ссылке `@…` вызывает `apk._arsc_values`, который сканирует весь resources.arsc (до 32 МБ, сжимается до десятков КБ), без запоминания и общего бюджета; `MAX_SVG` проверяется только в конце. Замер: один вызов на 30 МБ arsc — 1,1 с, один вектор (~4000 вызовов) — около 75 минут под `download_lock` в единственном потоке обработчика (IPA и APK) или в ночной проверке; хватает APK, подписанного любым ключом, из GitHub, по ссылке, из 4PDA или своей загрузкой.
**Proposal:** разбирать arsc один раз в индекс `{id: значения}` внутри `render_icon`, запоминать `drawable()` по имени файла, ввести общий бюджет разрешений и узлов (порядка 2000) с отказом, проверять `MAX_SVG` по ходу построения. Дополнительно — рендер в подпроцессе с таймаутом.
**Status:** open

## 2026-11-12 · read_apk: central directory без предела — файл до 1 ГиБ раздувает процесс до ~9 ГиБ памяти [P2]
**Context:** адверсариальный аудит 2026-11-12, линза «недоверенный ввод» (замер верификатора на Python 3.14), `appshelf/apk.py:70` (`read_apk`, также `extract_icon`/`resource_icon`); вызовы `appshelf/android/sources.py:244,308`, `appshelf/android/fetch.py:76,200,211`.
**What:** `zipfile.ZipFile` строит `ZipInfo` на каждую запись central directory (~490 Б против 52 Б в файле) ещё до проверки манифеста и подписи. **Proposal:** до `ZipFile` читать EOCD самостоятельно и отвечать `ApkError`, если CD больше ~16 МиБ или записей больше ~100 000; те же пределы — в `extract_icon`/`resource_icon`. Страховка — `MemoryMax` в `appshelf-web.service` и `appshelf-nightly.service`.
**Status:** open
