# Несколько человек в одном браузере — дизайн

**Дата:** 2026-10-12 · **Статус:** реализован; ручные проверки — §8; изменение 2026-10-13 — новый Apple ID из
«Добавить» становится отдельным человеком (§2, §4) · **Основа:**
[2026-10-08-multi-apple-id-design.md](2026-10-08-multi-apple-id-design.md) (что здесь не сказано — как там)

«Человек» — строка `users`, в панели он называется участником; «полка» — Apple ID (`accounts`) с его историей,
каталогом и IPA.

## 1. Зачем

В модели 2026-10-08 Apple ID принадлежит одному человеку, а браузер вошёл ровно как один человек. Этого не
хватает, когда набор Apple ID зависит от устройства:

- на одном устройстве нужны два Apple ID сразу, на другом — только один;
- Apple ID общий: им пользуются несколько людей, у каждого рядом свой личный, а где-то он единственный.

Связка «человек → его Apple ID» для общего Apple ID не годится: вход любым Apple ID связки открывает все её
полки, то есть знающий пароль общего Apple ID увидел бы и личную полку. А подключить к себе Apple ID другого
человека панель отказывается («уже у другого участника»).

Решение: люди и их Apple ID остаются как есть, а **браузер может быть вошедшим сразу как несколько человек**.
Общий Apple ID — отдельный человек; кому он нужен, входит им на своём устройстве в дополнение к своему или
только им.

### Критерии успеха

1. В браузере человека X «Добавить Apple ID» с Apple ID человека Y (пароль → код 2FA) → в шапке полки обоих,
   переключение без входа; Y остаётся отдельным человеком (строки `users` и `accounts` не меняются).
2. Браузер, вошедший только как Y, видит только полки Y; страницы и приложения полок X ему недоступны.
3. Y подключён в браузерах X и Z одновременно: каждый видит свои полки и полки Y, личные полки друг друга — нет.
4. «Убрать с этого устройства» убирает одного человека, остальные входы живы; «Выйти» убирает всех.
5. «Выйти на всех устройствах» у Y гасит Y во всех браузерах и не трогает вход X в тех же браузерах.
6. Cookie, выданные до выкладки, работают без повторного входа.
7. Запасная ссылка, открытая в уже вошедшем браузере, добавляет человека, а не заменяет вошедших.
8. «Участники» открыты, когда владелец среди вошедших, при любой активной полке; без владельца — 403.

### Вне рамок

Общий каталог нескольких полок на одной странице; перенос Apple ID между людьми и выделение Apple ID из связки
в отдельного человека; права на общую полку — каждый, кто вошёл общим Apple ID, полный хозяин его полки
(публикует, снимает, удаляет), как и сейчас; поведение iOS (§8, проверяется вручную).

## 2. Решения, принятые при обсуждении

| Вопрос | Решение | Почему |
|---|---|---|
| Что меняется | Сессия браузера: список людей вместо одного | Состав Apple ID задаёт устройство; база не меняется |
| Общий Apple ID | Отдельный человек — как сейчас после входа по приглашению | Вход им открывает только его полку |
| Успешный вход | Добавляет человека в браузер, вошедших не заменяет | «Войти заново» на одной полке не должен выбрасывать остальных; одно правило для формы входа, «Добавить», приглашения и запасной ссылки |
| «Добавить» Apple ID, который есть у другого человека | Вход в Apple → браузер входит и как он | Требование владельца; пароль и код этого Apple ID и так открывают его панель через `/login` |
| «Добавить» Apple ID, которого на сервере нет | Отдельный человек, браузер входит и как он (*изменено 2026-10-13*; было — к человеку активной полки) | При активной общей полке личный Apple ID доставался общему участнику: его полку видел и удалял каждый, кто входит общим Apple ID. Владелец: новый Apple ID никому не достаётся, на каждом устройстве входят каждым Apple ID. Новых связок «человек → несколько Apple ID» нет (2026-10-08, критерий 2 — только для прежних) |
| «Выйти» в шапке | Все люди этого браузера | На чужом устройстве «Выйти» не должен оставлять доступ |
| «Участники» | Доступны, если владелец среди вошедших | Управление не прячется из-за активной чужой полки |
| Срок входа | У каждого человека свой — год с его входа | Вход соседа не продлевает чужой вход без проверки |

Отвергнуто: перенос Apple ID к другому человеку (общий Apple ID открывал бы личные полки); один Apple ID у
нескольких людей (перестройка схемы и правил владения полкой, а состав по устройствам всё равно не различается);
отказ от сущности человека (переписывание модели 2026-10-08, теряется «вход любым открывает все мои полки»).

## 3. Сессия

### Cookie

`appshelf_auth` — записи через `|`, по одной на человека. Запись прежняя:
`<user_id>:<epoch>:<expires>:<HMAC(cookie-key, user_id \0 epoch \0 expires)>`, каждая подписана отдельно.

- **Чтение.** Каждая запись проверяется сама: подпись, срок, `epoch`, человек существует. Негодная пропускается,
  остальные действуют; у повторившегося человека считается первая годная. Порядок людей — порядок записей, то
  есть порядок входа.
- **Вход человека U.** Годные записи остальных переносятся как есть, со своим сроком. Запись U — новая: на
  месте его прежней, а если её не было — в конце. Повторный вход порядок полок в шапке не меняет.
- **Убрать человека.** Cookie без его записи; записей не осталось — cookie удаляется.

Cookie версии 2026-10-08 — список из одной записи. Записей не больше, чем людей на сервере (~90 байт на
запись) — отдельного предела нет. Прежний код cookie с двумя записями не разберёт и сочтёт негодной: откат
выкладки означает повторный вход в таких браузерах.

### Вошедшие, полки, активная полка

- **Вошедшие** — люди годных записей. **Полки браузера** — Apple ID всех вошедших: по порядку людей, внутри
  человека — по `id`. Полок нет — как без cookie.
- **Активная полка** — `appshelf_acct`, если она среди полок браузера; иначе первая.
- **Человек активной полки** — из его панели идёт «Добавить» (§4): до конца шага он должен оставаться вошедшим.
- **Владелец в браузере** — вошедший с ролью `owner`.

В `request.state`: `users` (вошедшие), `user` (человек активной полки), `accounts` (полки браузера), `acct`
(активная полка).

## 4. Вход

Успех любого входа → запись человека в cookie (новая или вместо его прежней), активная полка — Apple ID,
которым вошли; у запасной ссылки — первый Apple ID человека.

| Путь | Против 2026-10-08 |
|---|---|
| `/login`, Apple ID есть на сервере | человек добавляется к вошедшим |
| `/login` по приглашению в уже вошедшем браузере | новый человек добавляется к вошедшим; плашка: «новый Apple ID станет отдельным участником, это устройство войдёт и как он» (было «перейдёт к нему») |
| `/apple/add`, Apple ID есть на сервере | у любого человека: вход в HOME этого Apple ID, затем человек добавляется к вошедшим. Отказа «уже у другого участника» нет |
| `/apple/add`, Apple ID на сервере нет | новый человек (участник, имя — из Apple) добавляется к вошедшим; приглашение не нужно; владельцу — письмо «новый участник» с именем того, из чьей панели добавили |
| `/l/<токен>` | человек добавляется к вошедшим |

Решение «идти ли в Apple» (2026-10-08 §4, шаг 1) прежнее во всём, кроме строки про `/apple/add`: неизвестный
Apple ID без приглашения до Apple не доходит. В потоке «Добавить» шаг кода и ошибки показываются формой
добавления (с шапкой) — и для Apple ID, который на сервере уже есть.

Лимиты, блокировки и срок шага кода не меняются. Счётчик неверных паролей — на Apple ID: у общего он один на
всех, кто им входит. Запасная ссылка владельца подключает общий Apple ID без пароля и кода.

## 5. Выход

| Действие | Маршрут | Поведение |
|---|---|---|
| «Выйти» (шапка) | `POST /logout` | удалить `appshelf_auth` и `appshelf_acct` |
| «Убрать с этого устройства» | `POST /logout/<user_id>` | cookie без записи человека → `/apple`; был последним — как «Выйти» |
| «Выйти на всех устройствах» | `POST /logout-all/<user_id>` | `users.epoch += 1` этого человека, его запись из cookie убрана → `/apple`; был последним — как «Выйти» |

`<user_id>` не среди вошедших → 404, ничего не меняется. `POST /logout-all` без человека удаляется.

## 6. Экраны

1. **Шапка.** Список полок браузера — адреса всех вошедших, переключение `/acct/<id>` как сейчас. «Участники» —
   если владелец среди вошедших.
2. **«Apple ID» `/apple`.** Группа на человека; вошедших больше одного — у группы заголовок: имя и роль. В группе
   — строки его Apple ID, как сейчас, с «Войти заново» и «Удалить полку» (было «Удалить» — не путать с «Убрать
   с этого устройства»); под ними — «Убрать с этого устройства» (вошёл один человек — кнопки нет: это было бы
   то же «Выйти») и «Выйти на всех устройствах». Внизу —
   «Добавить Apple ID» и подсказка: вход Apple ID открывает полки его участника, остальные подключаются на
   устройстве отдельно.
3. **«Добавить Apple ID» `/apple/add`.** Подсказка: Apple ID, который уже есть на сервере, подключится к этому
   устройству вместе со своей полкой; новый станет отдельным участником со своей полкой — это устройство войдёт
   и как он, на других устройствах им входят отдельно.
4. **Удаление полки.** «Последний Apple ID владельца удалить нельзя» решается по человеку полки: он владелец
   и Apple ID у него один; удаление перепроверяет это под своей транзакцией — два удаления разных его полок в
   один момент не оставят сервер без владельца. После удаления: в браузере остались полки → `/apple`; нет →
   `/login` без cookie.
5. **«Участники» `/admin`.** «Себя удалить нельзя» и скрытая кнопка «Удалить» — про владельца, а не про
   человека активной полки. Человека, вошедшего в этом же браузере, владелец удалить может: его запись в cookie
   перестаёт действовать. «Выйти везде» самому себе → `/`: «Участники» этому браузеру уже закрыты.

## 7. Безопасность и ошибки

- Записи cookie подписаны по отдельности, подпись покрывает человека, `epoch` и срок: чужую запись не собрать
  и не продлить, перестановка и склейка ничего не дают.
- `account_id` — по-прежнему только из серверной сессии: активная полка — одна из полок браузера; `app_id`
  ищется в её пределах, чужой → 404.
- Действия владельца проверяют роль среди вошедших на сервере; без владельца → 403.
- Новые POST-маршруты закрыты той же проверкой `Origin`: чужой сайт не добавит человека в браузер и не уберёт.
- «Добавить» Apple ID другого человека теперь доходит до Apple. Нового это не открывает: тот же Apple ID
  принимает и `/login`, с теми же лимитами.
- `GET /acct/<id>` по ссылке с чужого сайта (`Sec-Fetch-Site: cross-site`) активную полку не переключает.

| Ситуация | Поведение |
|---|---|
| Запись негодна (срок, `epoch`, человека удалили) | пропускается молча, остальные действуют |
| Негодны все записи | как сейчас — на `/login` |
| Активная полка недоступна (человека убрали, полку удалили) | первая полка браузера |
| Убрали или погасили последнего человека | как «Выйти» |
| Удалена последняя полка человека, в браузере есть другие | человек удалён, страница `/apple` |
| Человека удалили или его входа в браузере уже нет («Выйти на всех устройствах», «Убрать с этого устройства», «Выйти»), пока он добавлял новый Apple ID | отказ после ответа Apple: участник не заведён, cookie не выдана, временный HOME удалён |

## 8. Тестирование

pytest, быстрый набор ≤ 60 с, время — только подменой.

- **Cookie:** несколько записей → несколько человек по порядку; негодная запись (подпись, срок, `epoch`,
  удалённый человек) пропускается, остальные действуют; запись версии 2026-10-08 читается; повторный вход
  заменяет запись человека, чужие сохраняют свой срок.
- **Вход:** «Добавить» Apple ID другого человека → полки обоих, `accounts.user_id` не изменился, подставной
  ipatool вызван в HOME этого Apple ID; второй браузер только с общим Apple ID видит только его, чужое
  приложение → 404; `/login` и запасная ссылка в уже вошедшем браузере добавляют человека; новый Apple ID из
  «Добавить» становится отдельным человеком и при активной общей полке — вход общим Apple ID из другого браузера
  его полку не открывает; верный код после «Выйти на всех устройствах» никого не заводит; шаг кода и ошибка в
  потоке «Добавить» — форма добавления.
- **Выход:** «Убрать с этого устройства» — один человек, остальные живы; последний — cookie удалена;
  «Выйти на всех устройствах» гасит человека в двух браузерах и не трогает соседа; чужой `user_id` → 404;
  «Выйти» удаляет всё.
- **Страницы:** `/apple` — группы по людям; «последний Apple ID владельца» — по человеку полки, а не по числу
  полок в браузере; удаление последней полки человека при живом соседе → `/apple`; `/admin` открыт владельцу
  при активной чужой полке и отвечает 403 браузеру без владельца; владелец не удаляет себя и удаляет
  вошедшего рядом человека.
- Тест отказа «уже у другого участника» (`test_adding_apple_id_of_another_person_is_refused`) заменяется.
- `manual`: на iPhone, где в App Store вошёл Apple ID X, установить приложение с полки Y и запустить. Записать:
  что спросил iOS, работает ли приложение после ввода пароля Y, остался ли в App Store X, не сработало ли
  правило 90 дней «Медиаматериалов и покупок». Итог — в вики проекта; отказ iOS панель не обходит — тогда
  подсказку каталога и README привести к тому, что показал iPhone. После выкладки — критерии 1–3 на живых
  устройствах.
