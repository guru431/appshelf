## 1. Зачем

appshelf ставит на iPhone приложения, которых нет в App Store. С Android та же беда, но в другой форме: телефон без
входа в Google Play или вообще без Play (Huawei, телефон без сервисов Google), российские банки удалены из Google Play,
а у части людей на телефоне нет ни одного магазина, которому они доверяют. Нужно то же, что для iPhone:

- приложения скачиваются на сервер из нескольких источников и ставятся на телефон **из браузера, со страницы полки**
  — без F-Droid, Obtainium, установщиков и других программ на телефоне;
- в панели два раздела — **Apple** и **Android**; по умолчанию открывается раздел той ОС, с которой открыли панель;
- в панель можно войти **Google-аккаунтом**, Apple ID и Google-аккаунт можно **связать**, Google-аккаунтов может быть
  несколько;
- есть **публичная Android-полка**: её наполняет владелец, а любой, кто знает **PIN из 6 цифр**, видит её и ставит
  приложения — только чтение и установка;
- новые версии подтягиваются ночью сами; на телефоне обновление — то же «Скачать APK» поверх установленного.

Android-приложение, в отличие от IPA, ни к чьему аккаунту не привязано: один и тот же APK банка годится любому. Поэтому
Android-полка принадлежит **участнику**, а не аккаунту, и источники, кроме Google Play, аккаунтов не требуют.

### Критерии успеха

1. На Android-телефоне без входа в Google Play: панель открывается сразу в разделе Android → «Добавить» → поиск
   «сбер» → СберБанк Онлайн из RuStore → через несколько минут в каталоге → «Скачать APK» → приложение ставится и
   запускается. Через день вышла новая версия в RuStore → ночью она на полке → «Скачать APK» ставит её поверх, данные
   приложения на месте.
2. Ссылка на APK с сайта банка (например, `https://acdn.t-bank-app.ru/download_apk/tbank_app.apk`) добавляется на полку;
   файл по ссылке сменился → ночью новая версия на полке. Ссылка на адрес локальной сети (`https://192.168.0.1/x.apk`,
   `https://localhost/…`, имя, которое резолвится в частный адрес) — отказ, сервер туда не ходит.
3. Свой APK загружается через страницу «Добавить» и ставится так же. Split APK (часть набора) — отказ с объяснением.
4. Новая версия приложения подписана другим ключом, чем текущая → текущей не становится; на карточке «подпись
   сменилась» и кнопка подтверждения; до подтверждения ставится прежняя.
5. Вход «Войти через Google» Google-аккаунтом, которого на сервере нет и приглашения нет → отказ; по приглашению →
   новый участник. Пароль Google сервер не видит (вводится на странице Google).
6. В браузере вошли Apple ID-участником A и Google-участником G → «Связать» → один участник; вход Google-аккаунтом G на
   другом устройстве открывает полки Apple ID участника A. Два участника, у каждого из которых есть Apple ID, не
   связываются.
7. Владелец подключает свой Google-аккаунт к Google Play → бесплатное приложение из Play, которое приходит одним
   файлом, добавляется на полку. Приложение, которое Play отдаёт только набором файлов, на полку не попадает, а полка
   предлагает тот же пакет из RuStore/AppGallery/F-Droid, если он там есть.
8. *Если подтвердит живая проверка (§14, шаг 0):* зарубежный Google-аккаунт владельца с покупками, подключённый через
   прокси своей страны, видит «Мои покупки» и скачивает купленное приложение на **свою** полку; на публичную полку и на
   полки других участников купленное не попадает.
9. Публичная полка: без PIN — только форма PIN; верный PIN → список и «Скачать APK», ничего больше (ни меню, ни чужих
   полок, ни действий). 20 неверных PIN с одного адреса → этот адрес закрыт на час; 100 со всех адресов за сутки →
   ввод закрыт новым гостям, владельцу письмо. Владелец сменил PIN → все гости вводят его заново, старые ссылки на
   файлы не работают.
10. Apple-часть работает как прежде: каталоги, ссылки установки, вход Apple ID, ночная проверка; база переходит на
    новую схему без ручных шагов.
11. Мастер-токена Google (AAS) и `oauth_token` нет в базе, логах, `jobs.error`, argv; пароля Google сервер не получает
    вовсе.

### Вне рамок

- Установка split APK, XAPK/APKS, OBB и Play Asset Delivery: браузер ставит только один APK (§3).
- Любая программа на телефоне: свой F-Droid-репозиторий, deep link Obtainium, установщики; фоновое обновление на телефоне.
- Склейка split APK в один и переподпись: обновление не встанет поверх оригинала, банки и защищённые приложения не
  запустятся.
- Платные приложения RuStore и AppGallery (нужен вход в их аккаунт с телефона, с сервера способа нет).
- Обход проверок лицензии и Play Integrity; запуск приложений, которым нужны сервисы Google, на телефоне без них.
- Публичная полка для Apple (IPA несёт данные покупателя — 2026-10-08 §1).
- Отвязка аккаунта от участника (есть удаление аккаунта: удалённый Google-аккаунт можно добавить заново отдельным
  участником); слияние двух участников, у каждого из которых есть Apple ID (решение 2026-10-13 остаётся).
- Знание, какая версия стоит на телефоне: страница этого не видит.
- Обход проверки разработчиков Google 2027 года (§3) — только подсказка на странице.
- Прямые ссылки Альфа-Банка и Озон Банка (сайты за антиботом): только «Свой файл» или RuStore.

### Чего допустить нельзя (даже если всё «работает»)

- Купленное приложение на публичной полке или на полке другого участника — это раздача чужой покупки.
- Тихая подмена приложения на полке APK с другой подписью (§7).
- Утечка мастер-токена Google или пароля в файлы, логи, вывод команд.
- Сервер, который по ссылке участника ходит во внутреннюю сеть (§6.2).
- Подбор PIN публичной полки или превращение её в открытое зеркало APK.
- Поломка Apple-части.

## 2. Решения, принятые при обсуждении

| Вопрос | Решение | Почему |
|---|---|---|
| Сценарий | Телефон без входа в Google Play или без магазина; ставить из браузера | Требование владельца |
| Источники | Все: RuStore, сайты банков (прямая ссылка), свой файл, Google Play, AppGallery, F-Droid, APKPure | Требование владельца; порядок подключения — §14 |
| Программы на телефоне | Нет: только браузер и страница полки; обновление — повторное «Скачать APK» | Требование владельца |
| Split-only приложения из Play | На полку не попадают; полка ищет тот же пакет одним файлом в RuStore/AppGallery/F-Droid | Браузер ставит один файл; склейка ломает обновления и банки (§3) |
| Разделы панели | Apple и Android; по умолчанию — раздел ОС устройства | Требование владельца |
| Вход Google | «Войти через Google» (OpenID Connect): сервер получает только личность | Требование владельца — вход Google-аккаунтом; пароль Google серверу не нужен и не передаётся |
| Несколько Google-аккаунтов | Да — как несколько Apple ID: несколько участников в браузере и несколько Google-аккаунтов у участника (через «Связать») | Требование владельца |
| Связка Apple и Google | Да, «Связать» двух участников, вошедших в этом браузере | Требование владельца |
| Скачивание из Google Play | Своим Google-аккаунтом, подключённым к Play; служебного общего аккаунта нет | Владелец: «зачем служебный, если пользователи будут указывать свой» |
| Публичная полка | Одна, Android; наполняет владелец своим Google-аккаунтом и любыми источниками; у гостя — только чтение и установка | Требование владельца |
| Защита публичной полки | Только PIN из 6 цифр + защита от перебора, 20 попыток | Требование владельца |
| Риск блокировки Google-аккаунта | Принимает владелец (его аккаунт качает для публичной полки) | Решение владельца |
| Android-полка | У участника, не у аккаунта *(решение исполнителя дизайна)* | APK ни к кому не привязан; участник только с Apple ID тоже ставит APK из RuStore |
| Купленное | Только на полку того участника, чей аккаунт купил *(решение исполнителя дизайна)* | Иначе раздача чужой покупки |
| «Связать» | Только если хотя бы у одного из двоих нет Apple ID *(решение исполнителя дизайна)* | Иначе пересматривается решение 2026-10-13 (общий Apple ID открыл бы личные полки); владелец просил связывать Apple с Google |
| Лимиты PIN | 20 неверных с адреса за час → адрес закрыт на час (числа — *решение исполнителя дизайна*); 100 неверных со всех адресов за сутки → ввод закрыт для **новых** гостей на сутки, вошедшие гости продолжают, владельцу письмо, открыть — кнопкой или сменой PIN (выбор владельца 2026-10-28) | Без общего предела 10⁶ PIN подбираются с множества адресов меньше чем за час (сеть IPv6 /48 — 65 536 подсетей /64); с ним — ~13 лет. Цена: посторонний может закрыть полку новым гостям на сутки |

Отвергнуто: свой F-Droid-репозиторий как канал установки (владелец: только браузер); служебный Google-аккаунт для
всех (владелец); вход паролем Google через сервер, как с Apple ID (Google не пускает пароли сторонних клиентов, а
мастер-токен из пароля дал бы серверу весь аккаунт); склейка split APK.

## 3. Проверенные факты (исследование 2026-10-28)

Проверено по первоисточникам и запросами к публичным API (с зарубежного и российского адресов); на живом сервере
appshelf и телефонах — **не проверялось** (это §14, шаг 0).

**Установка на телефоне.**
- Браузер ставит один APK после разрешения «Установка неизвестных приложений» для браузера. Набор split APK — только
  через сессию `PackageInstaller` из установленного приложения; веб-страница так не может
  (developer.android.com/reference/android/content/pm/PackageInstaller).
- Android 14 не ставит `targetSdk < 23`, Android 15 — `< 24`. Для APK из браузера действуют «ограниченные настройки»
  (спецвозможности, уведомления, SMS — разблокировка вручную). Samsung Auto Blocker (One UI 6.1.1+, по умолчанию
  включён) блокирует установку и обновления не из Galaxy Store/Play; у Huawei — «Режим без угроз» (Pure Mode). Play
  Protect может предупреждать («Все равно установить» — так прямо пишет Газпромбанк).
- Обновление ставится только APK с той же подписью; иначе — удалить приложение вместе с данными. RuStore называет
  банки самым частым случаем конфликта подписей (rustore.ru/help/users/start/installation-and-update-errors).
- Отдавать APK лучше с `Content-Type: application/vnd.android.package-archive` и `Content-Disposition: attachment;
  filename="<пакет>-<версия>.apk"`: с `application/zip` Chrome сохраняет `.apk.zip`.
- **Проверка разработчиков Google:** с 2026-09-30 — Бразилия, Индонезия, Сингапур, Таиланд и только установка из 7
  магазинов; **с 2027 — все приложения на сертифицированных устройствах по всему миру, включая установку не из
  магазина**; исключения — ADB, разовый «advanced flow» (режим разработчика → сутки ожидания → биометрия) и страны под
  всеобъемлющими санкциями (Россия, по формулировке Google, вероятно, не входит) — developer.android.com/developer-verification.
  Банки под санкциями, скорее всего, не зарегистрируются. Это прогноз, не факт.

**RuStore** (неофициальный API, проверено 2026-10-28).
- `GET https://backapi.rustore.ru/applicationData/overallInfo/<пакет>` с заголовком `ruStoreVerCode: 1105002` →
  `appId`, `versionName`, `versionCode`, `appVerUpdatedAt`, `price`, `signature` (SHA-256 сертификата). Без
  заголовка — 400 (с июля 2026).
- `POST /applicationData/v2/download-link` с `withoutSplits: true` → один универсальный APK; `POST
  /applicationData/download-link` → `.zip`-обёртка (тот же путь с `.apk` — сам APK). Поиск: `GET
  /applicationData/apps?query=…&pageSize=…&pageNumber=…`.
- Подпись — ключом разработчика: сертификат скачанного APK совпал с полем `signature` (Сбер, фонарик); ВТБ и Т-Банк
  совпали с AppGallery.
- Есть Сбер, ВТБ, Альфа, Т-Банк, Mir Pay, Госуслуги Ключ, VK, Ozon. Платные — `price > 0`, скачивание без входа → 403.
- VK закручивает API: клиенты переходят на `/v3/…` с nonce и HMAC; повторные запросы подряд обрывались (лимит?).
  CDN `static-m.rustore.ru` — сертификат Russian Trusted Sub CA, `static.rustore.ru` — общепризнанный.
- Правила RuStore (ред. 03.08.2026) — личное некоммерческое использование, запрет сбора контента и обхода защиты.

**Сайты банков** (2026-10-28, российский адрес): прямые ссылки на официальных доменах есть у Сбера
(`https://cdnweb.sberbank.ru/appdistr/SberbankOnline.apk`), ВТБ (`https://vtb.com/apk/vtbonline.apk` → редиректы),
Т-Банка (`https://acdn.t-bank-app.ru/download_apk/tbank_app.apk`), Газпромбанка
(`https://mob.cdn.gpb.ru/media/mobile/apk/new_version/android_inapp/android_inapp.apk`). Версия — из самого APK; признак
смены — `ETag`/`Last-Modified`/`Content-Length`. Альфа и Озон — антибот на JavaScript; Россельхозбанк для частных
клиентов APK не раздаёт. Часть доменов — с сертификатом НУЦ Минцифры.

**Google Play.**
- Скачивание с сервера — неофициальный протокол `/fdfe/*`: `details`/`bulkDetails` (versionCode), `purchaseHistory`
  (покупки), `delivery` (base + splits + OBB). Инструменты: apkeep (EFF, Rust) 1.1.0 от 2026-10-01 — бесплатные
  приложения, splits, но **платные не качает и версию не печатает**; gplayapi (Aurora, Kotlin AAR) — покупки умеет, на
  сервере без переделки не запускается.
- Вход: `oauth_token` из cookie страницы `accounts.google.com/EmbeddedSetup` (одноразовый, ~10 минут) → обмен на
  мастер-токен AAS (живёт до смены пароля). С марта 2026 Google требует в обмене `droidguard_results` (apkeep 1.0.0
  починил). Мастер-токен даёт доступ не только к Play.
- **Россия:** с 2022 «Google Play is blocking the downloading of paid apps and updates to paid apps in Russia»; ранее
  купленное, которого нет на устройстве, не скачать; бесплатное доступно
  (support.google.com/googleplay/android-developer/answer/11950272). Критерий «в России» Google не раскрывает. Страна
  Play = страна платёжного профиля, смена — раз в 90 дней и только находясь в стране. Слабый сигнал (4pda): с
  иностранным профилем и через VPN купленное скачивалось. **Гипотеза:** купленное отдаётся аккаунту с нероссийской
  страной Play при нероссийском IP.
- Удалённое из Play (банки под санкциями) переустановить нельзя (answer/12246761) — это не App Store.
- Почти всё в Play — App Bundle, то есть splits; одним файлом приходят только старые приложения.
- Без Play Store на телефоне: проверка лицензии (LVL) не проходит; «automatic integrity protection» (pairip) показывает
  «Get this app from Play» (по данным AppBrain — у четверти популярных и большинства новых приложений). Часть платных
  без проверки работает.
- Aurora предупреждает: Google может заблокировать аккаунт за сторонний клиент «forever».

**AppGallery:** `POST https://store-drru.hispace.dbankcloud.ru/hwmarket/api/clientApi` (`client.front2` → `sign`,
затем `client.appDetailById`) → версия и прямая ссылка на универсальный APK; без входа. App Signing Huawei может
переподписать своим ключом — сертификат сверять. С зарубежного IP — зона US, поиск банков не находит. Правила
запрещают автоматический доступ.

**F-Droid:** подписанный индекс (`entry.jar`/`entry.json` → `index-v2.json`, ~70 МБ), APK — одиночные (бывают по ABI),
подпись F-Droid или разработчика (reproducible builds). Банков нет.

**APKPure:** `api.pureapk.com` без входа, APK или XAPK; зеркалит Play, банков РФ нет; были подмены: 2021 — троян в
клиенте, 2025-10 — Telegram X с бэкдором (Dr.Web). Правила запрещают выкачку.

## 4. Модель: участники, аккаунты, полки

| Сущность | Что это |
|---|---|
| Участник (`users`) | как сейчас; теперь у него Apple ID (`accounts`) **и/или** Google-аккаунты (`google_accounts`) |
| Apple ID | как сейчас: своя Apple-полка |
| Google-аккаунт | личность для входа (`sub` OpenID); по желанию — подключение к Google Play |
| Android-полка участника | одна на участника; появляется при первом добавлении приложения |
| Публичная полка | одна на сервер, Android; хозяин — владелец сервера |

- Участник, у которого есть только Google-аккаунт, — обычный участник: Apple-раздел у него пуст, с подсказкой «Добавить
  Apple ID».
- Участник удаляется, когда удалён его последний аккаунт любого вида (было — последний Apple ID). «Последний Apple ID
  владельца удалить нельзя» — как сейчас: у владельца всегда есть Apple ID, и при связке он всегда остаётся (§5)
  *(решение исполнителя дизайна)*.
- Сессия браузера — как в 2026-10-12: список участников. В Android-разделе активная полка — Android-полка одного из
  вошедших или публичная; выбор — в меню шапки, как полки Apple ID.

## 5. Вход через Google и связка

### Вход

OpenID Connect, Authorization Code + PKCE, `state` и `nonce`, `scope=openid email profile`,
`prompt=select_account` (выбор из нескольких Google-аккаунтов браузера). Ключ Google-аккаунта — `sub`, адрес — для
показа. Настройки — `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` в `appshelf.env`; адрес возврата —
`<APPSHELF_PUBLIC_BASE>/google/callback` (точный путь — исполнителю). Нет настроек — кнопки нет. Владелец один раз
заводит клиент OAuth в Google Cloud Console (бесплатно; для `openid email profile` проверка приложения Google не
нужна) — шаги в README.

После ответа Google, как для Apple ID (2026-10-08 §4, 2026-10-12 §4):

| Случай | Решение |
|---|---|
| `sub` есть на сервере | вход его участником, добавление к вошедшим |
| Нет; действующая cookie приглашения | новый участник (`member`) |
| Нет; «Добавить Google» из панели вошедшего | новый участник, добавляется к вошедшим; владельцу письмо «новый участник» |
| Иначе | «Этот Google-аккаунт на сервере не зарегистрирован — нужна ссылка-приглашение» |

Лимиты Apple (неверный пароль) здесь не нужны: проверку пароля делает Google. Cookie участника — та же
`appshelf_auth` (год, своя запись).

### Связка

На странице «Аккаунты», когда в браузере вошли двое и **хотя бы у одного из них нет Apple ID**: «Связать <B> с <A>» →
страница подтверждения → Google-аккаунты B и его Android-полка переходят к A, B удаляется, запись B в cookie
убирается (A в ней уже есть). Вошедшими в обоих аккаунтах на этом устройстве человек доказал, что владеет обоими.

- **Кто остаётся (A), решает сервер, не человек** *(решение исполнителя дизайна)*: участник с Apple ID; если Apple ID
  нет ни у кого — владелец, иначе тот, чья запись в cookie раньше. **Apple ID никогда не переходит к другому
  участнику** — правило 2026-10-13 и `CLAUDE.md` для Apple ID не меняется. Владелец всегда остаётся: у него всегда есть
  Apple ID (§4).
- Совпавший пакет на обеих Android-полках — остаётся у A, у B удаляется с файлами.
- Подсказка на странице: связка необратима; аккаунт, которым пользуются несколько человек, не связывать — вход им
  откроет все полки участника.

### Раздел по умолчанию

`/` по `User-Agent`: `Android` → Android-раздел, iPhone/iPad/iPod → Apple-раздел как сейчас. Иное (компьютер, iPad в
режиме «как Mac») → раздел, открытый последним (cookie), без неё — Apple. Переключатель Apple/Android — в шапке
каждого раздела; на телефоне он не меняет раздел по умолчанию *(решение исполнителя дизайна)*.

## 6. Источники APK

Общее для всех: результат — **один APK**; разбор и проверки — §7; скачивание — общей очередью и блокировкой
скачивания, проверка места как у IPA (≥ 4 ГБ свободно и локально, и в архиве). Ошибка источника ставит
приложению `error`, остальное не трогает. Запросы к одному источнику — последовательно, с паузой (число — исполнителю).

**Источник — у карточки, его можно сменить** *(решение исполнителя дизайна)*. Пакет на полке один; найденный в
поиске пакет, который уже на полке, показан «на полке» с отпечатком подписи этого источника. «⋯ → Сменить источник»
(например, RuStore сломался — взять с сайта банка): версии и закрепления остаются, у каждой версии записан её
источник; первая версия из нового источника подчиняется правилу подписи §7 — другой сертификат текущим не станет без
подтверждения. «Свой файл» можно загрузить новой версией на любую карточку (пакет совпадает, правило подписи то же);
источник карточки при этом не меняется.

### 6.1 RuStore

Поиск, сведения, скачивание универсального APK (§3). Платные (`price > 0`) в выдаче помечены «платное — недоступно».
Подпись скачанного должна совпасть с `signature`, иначе — ошибка «подпись не совпала с RuStore». Ночная проверка —
`overallInfo`, `versionCode` больше текущего → скачать. Заголовок версии клиента RuStore — константа в коде; когда VK
закроет v1/v2, источник ломается до переделки — приложения остаются на полке и ставятся. TLS: проверка сертификата не
отключается; если CDN отдаёт сертификат НУЦ, исполнитель добавляет его корень в доверенные **только для загрузчика
источников**.

### 6.2 Прямая ссылка

Только `https`. Перед каждым запросом (и после каждого редиректа) имя резолвится, и если хоть один адрес частный,
loopback, link-local, multicast или зарезервированный — отказ; соединение — на проверенный адрес. Не больше 5
редиректов, размер — не больше 1 ГБ. Ночная проверка — `HEAD` (или `GET` с `Range: bytes=0-0`): изменились `ETag`,
`Last-Modified` или `Content-Length` → скачать; `versionCode` больше текущего → новая версия, иначе отметка
«проверено, новее нет». Сертификаты НУЦ — как в 6.1.

### 6.3 Свой файл

Загрузка из браузера (до 1 ГБ), потоком во временный файл. Новая версия — загрузкой нового файла на ту же карточку
(пакет должен совпасть). Ночью не проверяется.

### 6.4 Google Play

**Подключение Google-аккаунта к Play** (страница «Аккаунты», у любого Google-аккаунта): инструкция → человек на
компьютере входит этим аккаунтом на `accounts.google.com/EmbeddedSetup`, копирует cookie `oauth_token` и вставляет в
форму → сервер обменивает его на мастер-токен. Адрес аккаунта из ответа обмена должен совпасть с адресом этого
Google-аккаунта, иначе отказ. Перед формой — предупреждение: сервер получит ключ с доступом к Google-аккаунту целиком,
не только к Play; владелец сервера технически может им воспользоваться; Google может заблокировать аккаунт за
сторонний клиент.

- Мастер-токен и профиль устройства (GSF ID, чек-ин) — в `/etc/appshelf/google/<id>/` (`appshelf`, 0700), как HOME
  ipatool. Не в базе, логах, `jobs.error`, argv (если инструмент берёт токен только аргументом — передавать файлом или
  окружением; argv виден в `/proc`).
- Прокси — на Google-аккаунт: имя из списка прокси в `appshelf.env` (формат — исполнителю), выбирает владелец. Нужен
  для страны аккаунта (§3, Россия).
- Токен отозван (смена пароля, блокировка) → «подключение к Play истекло», баннер; письмо — только по аккаунтам
  владельца, одно на эпизод (как Apple ID).

**Бесплатные.** В поиске «Добавить» — источник Google Play, если у участника (для публичной полки — у владельца) есть
подключённый аккаунт; несколько — выбор аккаунта. Приложение добавляется, только если `delivery` отдаёт **один APK**
без splits, OBB и пакетов ресурсов; иначе — строка «набором файлов — из браузера не ставится» и, если пакет есть в
RuStore/AppGallery/F-Droid, кнопка взять оттуда (с подписью для сравнения). Удалённое из Play — «недоступно».

**Купленное.** «Мои покупки» подключённого аккаунта (`purchaseHistory`) → «Добавить» → только на Android-полку
участника, которому принадлежит аккаунт. На карточке: «может потребовать Play Store для проверки лицензии». На
публичную полку купленное не добавляется (проверка на сервере, не только в интерфейсе); при «Связать» переходит вместе
с аккаунтом.

**Ночью** — `bulkDetails` по аккаунту, `versionCode` больше → скачать. Новая версия пришла splits'ами — текущая
остаётся, отметка «новая версия только набором файлов».

**Инструмент — исполнителю.** apkeep не покрывает покупки и версии; вероятно, свой небольшой клиент протокола
(`details`, `bulkDetails`, `purchaseHistory`, покупка-доставка) на мастер-токене, полученном обменом (сам или apkeep).
Решается по итогам живой проверки (§14, шаг 0).

### 6.5 AppGallery, F-Droid, APKPure

- **AppGallery:** поиск и сведения (§3), универсальный APK. Если пакет есть в RuStore — в выдаче сравнение
  сертификатов; не совпал — отметка «подписан не так, как в RuStore: не встанет поверх версии оттуда».
- **F-Droid:** официальный репозиторий; подпись индекса проверяется; из вариантов по ABI — универсальный, иначе
  `arm64-v8a`.
- **APKPure:** только одиночный APK. Если пакет известен из другого источника — сертификат должен совпасть. Если нет —
  добавление после подтверждения «APKPure распространял подменённые APK; подпись не с чем сверить» и метка «подпись не
  сверена»; дальше обновления — только с той же подписью.

**Как сделано (этап 5, 2026-10-29; план — `docs/superpowers/plans/2026-10-28-android-stage5.md`, живая проверка —
`tests/data/{appgallery,fdroid,apkpure}/README.md`).** Отступления от пунктов выше:
- **F-Droid — подпись индекса не проверяется** (решение плана): APK берётся по HTTPS с `f-droid.org` через пакетный
  API, подпись приложения задаёт первая версия на полке, как у ссылки. Проверка индекса — это `index-v2.json` (десятки
  МБ JSON в памяти appshelf-web) и своя проверка подписи JAR; выигрыш против HTTPS и правила подписи мал.
- **AppGallery и F-Droid — ссылкой, не поиском** (решение плана): «По ссылке» понимает страницы магазинов (и ID
  AppGallery), поиск — только RuStore. Сравнение подписи с RuStore — после скачивания меткой на карточке, а не в выдаче.
- **AppGallery — `client.updateCheck` по имени пакета** (клиент UpdateSDK), а не `client.front2` → `client.appDetailById`
  из §3: живьём `appDetailById` с `sign` не отвечает. ID со страницы → пакет — переадресацией `appdl/<ID>`. Признака
  платного в ответе нет (платные не находятся).
- **APKPure — «известен из другого источника» = есть в RuStore** (или у карточки уже есть версия — тогда работает общее
  правило подписи §7): с RuStore подпись обязана совпасть, иначе отказ.
- **F-Droid ночью — по рекомендуемой версии**, не по `versionCode`: рекомендуемая сборка бывает x86_64, а на полке —
  ARM-сборка с другим кодом.
- **Split-only из Google Play** (§6.4): вместо кнопки «взять оттуда» с подписью для сравнения — строка «есть в RuStore,
  AppGallery, F-Droid — смените источник» (запись в `FINDINGS.md`).

## 7. APK: разбор, подпись, версии, хранение

**Разбор** (чем — исполнителю; предпочтительно без JVM): пакет, `versionCode`, `versionName`, `minSdk`, `targetSdk`,
название, иконка, ABI, SHA-256 сертификата подписи (схемы v2/v3, иначе v1). Отказ: split APK (`split`,
`isSplitRequired`, `requiredSplitTypes`), без подписи, не разбирается. `targetSdk < 24` — предупреждение «Android 15+
не поставит», не отказ. Иконка — из APK, иначе из источника, иначе заглушка.

**Подпись.** Первая версия задаёт ожидаемый сертификат приложения на полке. Новая версия с другим сертификатом
скачивается, но текущей не становится: «подпись сменилась — обновление не встанет поверх, приложение придётся удалить
с данными» и кнопка «Принять новую подпись». На карточке — короткий отпечаток сертификата и подсказка: стояло из
Google Play с другой подписью — сначала удалить.

**Версии** — как у IPA: текущая, предыдущая, закреплённые; старее предыдущей удаляется.

**Хранение:** `<архив>/<токен полки>/<пакет>-<versionCode>/{<пакет>-<versionName>.apk, icon.png}`; у Android-полки
участника и у публичной — свой случайный токен (как `accounts.shelf`); смена — `appshelf rotate-token` (расширить на
Android-полки). Один APK на нескольких полках хранится в каждой отдельно *(решение исполнителя дизайна: проще, CIFS)*.

**Раздача** — Apache `/d/`, как IPA: `AddType application/vnd.android.package-archive .apk`, `Content-Disposition:
attachment` (образец vhost — дополнить). Ссылки на файлы — по неугадываемому пути, без cookie: PIN защищает страницу
публичной полки, а не файлы — как и с IPA.

## 8. Публичная полка

- Выключена, пока владелец не задал PIN. Владелец на вкладке «Публичная»: задать/сменить PIN, добавить приложение
  (та же «Добавить» с выбором «моя полка / публичная»), снять, закрепить версию. Купленное — нельзя (§6.4).
- Участники видят её во вкладке «Публичная» без PIN.
- Гость: адрес публичной полки (путь — исполнителю) → форма PIN → cookie гостя (подписанная, с эпохой PIN, 90 дней)
  → список с «Скачать APK» и подсказками по установке. Ни шапки с меню, ни вкладок, ни действий.
- PIN — 6 цифр, в базе — хэш с солью; смена → эпоха PIN `+1`, cookie гостей недействительны, и **у публичной полки
  новый токен каталога** (перенос как `rotate-token`): пересланные раньше ссылки на файлы перестают работать
  *(решение исполнителя дизайна)*. Пока PIN не менялся, ссылка на файл работает без PIN — как ссылки на IPA.
- **Перебор:** 20 неверных с адреса за час → адрес закрыт на час (IPv6 — по /64). 100 неверных со всех адресов за
  сутки → ввод PIN закрыт для новых гостей на сутки («ввод PIN временно закрыт»); гости с действующей cookie
  продолжают; владельцу одно письмо на эпизод; на вкладке «Публичная» — «Открыть ввод PIN» (сбрасывает общий счёт) и
  смена PIN (тоже открывает). Счётчики — в базе
  (перезапуск при выкладке их не сбрасывает). Адрес клиента — из `X-Forwarded-For`, который ставит Apache (иному
  источнику заголовка не верить). На форме — «осталось N попыток».

## 9. Задания и ночная проверка

- Обработчик заданий (поток в `appshelf-web`) берёт и Android-задания: добавить, повторить, проверить обновление.
  Общая блокировка скачивания — одна на сервер (IPA и APK качаются по одному). Задания Google Play ждут, пока у
  аккаунта нет действующего подключения.
- Ночная проверка после Apple ID обходит Android-полки (участников и публичную): по источнику — §6. Итог — в
  `nightly_result` строкой «Android: обновлено N, без изменений M, ошибок K». `nightly.stamp` — в конце, как сейчас.
- Ошибка одного источника не останавливает остальные.

## 11. Безопасность и ошибки

- Права: участник действует только на своей Android-полке; публичной управляет только владелец (проверка роли на
  сервере); гость — только чтение. Пакет в адресе ищется в пределах активной полки, чужой → 404.
- `oauth_token` — только в памяти обработки формы; мастер-токен — только файлом в `/etc/appshelf/google/<id>/`.
  Удаление Google-аккаунта удаляет его каталог.
- Прямая ссылка — защита от обращения во внутреннюю сеть (§6.2), в том числе после редиректов и при повторном резолве.
- Загрузка файла — предел размера в Apache и в приложении; файл не исполняется, только разбирается.
- POST — та же проверка `Origin`.
- Правила RuStore, AppGallery, APKPure и Google Play запрещают автоматическое скачивание; риск блокировки доступа или
  аккаунта принят владельцем (§2). Запросы — последовательно, с паузами, ночная проверка — раз в сутки.

| Ситуация | Поведение |
|---|---|
| Источник ответил ошибкой или сменил формат | `error` у приложения с текстом, «Повторить»; полка и прежние версии работают |
| Split-only / OBB / платное без покупки | не добавляется, понятная причина |
| Подпись не совпала с источником (RuStore `signature`) | ошибка, файл удалён |
| Подпись новой версии сменилась | §7 |
| Подключение к Play истекло | баннер; задания ждут; письмо по аккаунтам владельца |
| Ссылка ведёт в частную сеть | отказ «адрес недоступен для сервера» |
| Мало места / архив недоступен | как у IPA |

## 13. Тестирование

pytest, быстрый набор ≤ 60 с, время — подменой; сеть — подставные ответы источников.

- **Разбор APK:** APK, собранный в тесте (или маленький образец в репозитории): поля, сертификат; split APK → отказ;
  без подписи → отказ.
- **Подпись:** вторая версия с другим сертификатом не становится текущей; после «Принять» — становится.
- **Источники:** RuStore — разбор ответов, несовпадение `signature`; ссылка — смена `ETag` → скачивание, та же версия →
  «новее нет»; **частные адреса** (IPv4, IPv6, редирект в частную сеть, имя с несколькими адресами) → отказ без
  соединения; Play — split-only не добавляется, купленное не уходит на публичную полку и на чужую.
- **Вход Google:** известный `sub`; неизвестный без приглашения → отказ; по приглашению; «Добавить Google»; неверный
  `state`/`nonce` → отказ.
- **Связка:** A (Apple) + G (Google) → один участник, cookie без G; оба с Apple ID → кнопки нет и POST → отказ;
  владелец не исчезает; совпавший пакет.
- **PIN:** 20 неверных с адреса → закрыт, через час открыт; 100 со всех → закрыто новым гостям, гость с cookie видит
  список, письмо одно, «Открыть ввод PIN» и смена PIN открывают; смена PIN гасит cookie гостей и меняет токен
  каталога; гость не открывает ничего, кроме списка.
- **Раздел по умолчанию:** User-Agent Android/iPhone/компьютер.
- **Изоляция:** чужая Android-полка, чужой пакет → 404; участник не управляет публичной.
- **Переход схемы:** база 4 → 5, повторное открытие ничего не меняет; Apple-данные на месте.
- `integration`: живой `overallInfo` RuStore; обмен и `details` Google Play — на сервере.
- `manual`: §14, шаг 0 и критерии 1–9 на живых устройствах (Android без Play, Samsung, Huawei если есть; «Войти через
  Google» в Safari и в веб-приложении с экрана «Домой» на iPhone — у веб-приложения iOS своё хранилище cookie, возврат
  из Google может не дойти до него; записать результат в вики).
